# Запись в 12:00 — инструкция для Claude Code

Задача: записать донора на сдачу тромбоцитов в окно 12:00 МСК. **Claude ведёт Царицыно вживую**
(смотрит на страницу и адаптируется к вёрстке), **бот параллельно ведёт Шаболовку и Беговую**.
Ровно одна заявка на все сайты.

Проект: `D:\blood-donor-bot`, Windows, Python в `.venv`. `.env` заполнен (логин, пароль, ключ
rucaptcha, Telegram). Перед стартом ничего не запущено, `state.json` без паузы.

## Что известно о сайтах (проверено 21.10)

Все три сайта — один движок (WordPress + плагин grampus), **сессии у сайтов независимые**,
но **на одном сайте у аккаунта одна сессия**: второй вход на тот же сайт выбивает первый.
Поэтому один сайт = один процесс. Никогда не запускай бота и live на одном и том же сайте.

| Сайт (name) | URL |
|---|---|
| tsaritsyno | https://donor-mos-zar.online |
| shabolovka | https://donor-mos-sab.online |
| begovaya | https://donor-mos.online |

Кабинет `/account/`:
- Таблица `table.needs-table`, строки `tr.dates-table__item`: `td.table-item__date` («24/10/2026»),
  `td.table-item__btn`.
- Свободная дата: `button[data-src="#modal-reservation"][data-select="<select name=time-reservation>…"]`.
- Мест нет: `button[data-src="#modal-forbidden"]` (окно «все свободные места закончились»).
  Прочерк «-» — дата не для записи.
- Клик по свободной кнопке → Fancybox-окно, в `.modal-reservation__inputs` вставляется `data-select`
  (select времени + скрытые `confirm-url`/`reject-url`), там же Яндекс SmartCaptcha (чекбокс),
  кнопка «Отправить» `[form-send]`.
- Отправка: POST `/wp-json/gse/form-v2/send` (multipart, поля формы + `smart-token` + `formsubmit`).
  Успех → редирект на `/account/?message=Вы успешно отправили заявку…&status=true`,
  ошибка → `status=false`.
- Свои заявки: `#modal-list-reservation .modal-list-reservation__body`
  (`.not-found` = записей нет, `.cancel-entry` = есть запись).
- **Ловушка:** на странице входа в тексте правил есть «кнопка «отменить запись»» — это НЕ запись.
- Новая дата (сегодня+3) появляется в таблице между ~12:00:20 и 12:01:30; 21.10 к 12:01:36 на всех
  сайтах уже была «места закончились». Реальную разметку окна выбора времени ещё никто не видел.

**22.10 узнали:**
- Сессия живёт ~55 с от входа (бот перелогинивается каждую минуту, у live то же самое).
  Капча при записи — с заданием (rucaptcha решает её 40–60 с), поэтому 22.10 отправка на Беговой
  получила `401 rest_not_logged_in`. Теперь бот перелогинивается перед «Отправить», если сессии больше
  `session_ttl_sec` (35 с), переносит токен капчи в новую форму и при 401 повторяет отправку один раз.
- Если `send.lock` занят, второй сайт ждёт до `send_lock_wait_sec` (60 с), а не сдаётся.
- 25/10 открылась в 12:00:20–12:00:28, к 12:01:30 мест уже не было.
- `/watch` у live падал (`Locator.click: Timeout`) из-за слетевшей сессии. Опрос через
  `POST /js` с `fetch('/account/')` работает, но раз в минуту возвращает страницу без таблицы
  (сессия слетела), и тогда нужен `/reload`.

**23.10 узнали:**
- 26/10 открылась на всех трёх сайтах в 12:00:00–12:00:08, к 12:00:17 (Беговая) и 12:01:03 (Царицыно)
  мест уже не было. Окно записи: select `time-reservation` с часами (08:00…12:00), как и ожидалось.
- **Ни одна отправка за 22–23.10 не прошла: все `401 rest_not_logged_in`.** Весь REST (`/wp-json/`)
  закрыт для незалогиненных, nonce не нужен. Сессия умирает через 30–60 с от входа (замер: жива на
  27 с, мертва на 36 с; в другой раз — на 45–49 с), активность её не продлевает.
- При ошибке отправки `script-jquery.js` сам уводит страницу на `?status=false` — окно теряется.
- Вход — простой POST `/auth.php` (`log`, `pwd`, `redirect_to`), без капчи. Сделан
  `SiteClient.fast_relogin()`: `fetch('/auth.php')` из открытой страницы (~1 с, окно и токен капчи
  остаются) + проверка `GET /wp-json/` == 200. Бот делает его перед «Отправить», если сессии
  > `session_ttl_sec` (теперь 10 с), и при вылете в опросе. Проверено на Царицыно 3/3.
- Беговая 23.10: капча прошла чекбоксом за 1 с, но полный перелогин съел 8 с — слот ушёл.
  Теперь там был бы быстрый вход и отправка к ~12:00:11.
- Live: **сразу перед** `[form-send]` вызови `GET /relogin` → `true` (это `fast_relogin`).

Правила центра: запись — это бронь, её подтверждает врач. Отклонённая заявка блокирует аккаунт
на 5+ часов; записи на близкие даты в разных отделениях не подтверждаются. Поэтому **одна заявка**.

## Защита от двойной заявки

`send.lock` в корне проекта. Бот берёт его перед «Отправить» сам. Claude берёт его через
`POST /lock` у live; `409` = бот уже отправляет → вторую заявку **не** отправлять.
Если отправка не удалась, бот снимает lock сам; если не удалась у Claude — удали `send.lock`.

## С 24.10: быстрый режим — все три сайта ведёт бот

`donor_bot/fast.py` (включён по умолчанию, `schedule.fast_mode`). Бот на все сайты, каждый в своём
потоке: `.venv\Scripts\python.exe -m donor_bot run` (запущен 23.10 13:42, ждёт 24.10 11:58:40).
Live на Царицыно больше не нужен — человек в цикле медленнее (23.10: 22 с от слота до отправки).

- 11:58:40 вход; токен капчи заранее: чекбокс в скрытом `#modal-reservation` (~1 с), свежий раз
  в 60 с через `smartCaptcha.reset()`; если чекбокс даёт задание (Шаболовка) — повтор раз в 30 с
  и запасные токены rucaptcha с перекрытием (~1 ₽ за штуку, только на таком сайте, до 12:05).
- Опрос: в странице фоновый `fetch('/account/')`, тело читается потоком до `</table>`; с 11:59:20
  новый запрос каждые 0,35 с, до 3 одновременно (сервер отвечает 0,5–2,5 с). Замер 23.10:
  1,2–2,8 ответа/с против 0,37 у старого бота.
- Сессия обновляется быстрым входом каждые 15 с; перед отправкой — только если старше 20 с.
- Слот найден → опрос стоп → один POST с полями как у сайта (сверено побайтно с запросом 23.10).
  401 → вход и повтор; отказ по капче → новый токен и повтор; повтор — только если заявки нет.
- Не проверено вживую: примет ли сервер токен капчи, полученный за 10–60 с до отправки
  (`captcha.token_max_age_sec`). Смотри `bot.log` и `network.jsonl` (`"dir": "fast-send"`).

## Шаги

**11:50–11:55 — запуск** (PowerShell, из `D:\blood-donor-bot`):

```powershell
Start-Process .\.venv\Scripts\python.exe -ArgumentList "-m","donor_bot","run","--site","shabolovka","--site","begovaya" -WorkingDirectory D:\blood-donor-bot
```

```bash
# живой браузер на Царицыно (Bash)
cd /d/blood-donor-bot; (.venv/Scripts/python.exe tools/live.py --site tsaritsyno > live_stdout.txt 2>&1 &)
# дождаться строки «готов» в live_stdout.txt, затем:

```

Проверка бота: `bot.log` → «сайты: shabolovka, begovaya», «следующая попытка: … 11:59:15 MSK».

**API live (`tools/live.py`)** — всё на `127.0.0.1:8777`:

| Запрос | Что делает |
|---|---|
| `GET /state` | url, видна ли форма входа, строки таблицы, открытые окна, «мои записи» |
| `GET /watch?sel=90` | обновляет кабинет ~раз в 2 с до 90 с; возвращается сразу при свободной дате (`data_select`, `free_btn_html`) или незнакомой странице |
| `GET /reload` | перезагрузить кабинет, при вылете — войти заново |
| `GET /relogin` | быстрый вход запросом без перехода (окно записи и капча остаются) |
| `GET /html?sel=CSS` | outerHTML элемента |
| `GET /text`, `GET /shot` | текст страницы / скриншот (путь к png — смотри через Read) |
| `POST /js` (тело — JS-выражение) | выполнить в странице |
| `POST /click` (тело — CSS) | клик по первому видимому |
| `POST /captcha` | пройти капчу как бот (чекбокс; задание — через rucaptcha) |
| `POST /lock` | взять `send.lock`; `"ok"` — можно отправлять, `409` — нельзя |

Все команды и AJAX/POST-запросы пишутся в `runs/<время>_live/tsaritsyno/network.jsonl`, дампы — там же.

**С 11:59:30 до 12:20 — Царицыно вживую:**
1. Крути `curl -s -m 120 "127.0.0.1:8777/watch?sel=90"` подряд.
2. Вернулся `data_select` → ближайшая свободная дата: `POST /click` по её кнопке
   (`tr:has(td.table-item__date:text-is("ДД/ММ/ГГГГ")) [data-src="#modal-reservation"]` или просто
   первая `[data-src="#modal-reservation"]`), `GET /shot` — посмотри окно.
3. Выбери самое раннее время: `POST /js` →
   `(() => { const s=document.querySelector('.fancybox__container select[name=time-reservation]'); const o=[...s.options].find(o=>o.value&&!o.disabled); s.value=o.value; s.dispatchEvent(new Event('change',{bubbles:true})); return o.text })()`.
   Если вёрстка другая — смотри `/html` / `/shot` и действуй по факту.
4. `POST /captcha` → `true`.
5. `POST /lock` → только при `"ok"`: `GET /relogin` (→ `true`), сразу `POST /click` с
   `.fancybox__container [form-send]`. Очередь у live одна: не держи параллельно `/watch`.
6. Итог: `/state` (url с `status=true`, «Список моих записей»). Скриншот.
7. Вернулся `login_form: true` / пустые `rows` → `/reload` и продолжай.

**После записи или в 12:20:**
- Убедись, что заявка одна (бот: `bot.log`, `state.json`; live: «Список моих записей»).
- Останови live (`Stop-Process` по `live.py`) и бота.
- Разбери `runs/*_live/tsaritsyno/` (`network.jsonl`, `live_free_slot.*`, скриншоты) и
  `runs/*_run/*/slot_*.html`, `network.jsonl` — допиши бота под реальную разметку окна записи
  (`donor_bot/site.py`, `_attempt_grampus`), добавь тест в `tests/test_grampus.py`,
  прогони `.venv\Scripts\python.exe -m pytest tests -q`.
- Если записи нет — запусти бота на все сайты на завтра: `python -m donor_bot run`.

## Нельзя

- Два процесса на один сайт (взаимное выбивание сессии).
- Вторая заявка при `409` от `/lock` или при уже существующей записи.
- Вводить пароль руками в браузер — вход только кодом бота из `.env`.
- Верить «отменить запись» на странице входа как признаку записи.
