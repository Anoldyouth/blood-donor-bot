# blood-donor-bot

Локальный бот, который в 12:00 по Москве пытается записать донора на сдачу
тромбоцитов в отделениях Центра крови им. О.К. Гаврилова через сайты
онлайн-записи. Сайты проверяются по приоритету, после первой успешной записи
остальные пропускаются.

| Приоритет | Сайт | Отделение |
|-----------|------|-----------|
| 1 | https://donor-mos-zar.online | Царицыно, Бакинская 31 |
| 2 | https://donor-mos-sab.online | Шаболовка, 57 |
| 3 | https://donor-mos.online | Беговая, Поликарпова 14 |

## Что известно о сервисе записи

Сайты открыть из облачной среды разработки не удалось (домены заблокированы
сетевой политикой), поэтому структура форм собрана из поисковой выдачи и
официального Telegram-канала центра:

* У всех трёх сайтов один движок («Сервис записи»): страницы `/account/`
  (вход и личный кабинет), `/account/register/`, `/forgot-pass/`.
* Слоты на донацию открываются **за 3 дня до даты в 12:00**.
* Запись — это **бронь**, которую затем подтверждает врач. При отклонении
  заявки аккаунт **автоматически блокируется на 5 и более часов**. Записи на
  близкие даты в разных отделениях не подтверждаются. Поэтому бот делает
  **ровно одну** запись и после успеха ставит себя на паузу
  (`pause_days_after_success`, по умолчанию 14 дней).
* Если кнопки записи в кабинете нет, значит компонентов вашей группы сейчас
  достаточно (так пишет сам сайт) — бот просто повторяет проверку.

Поскольку реальная вёрстка не видна, бот работает **эвристически**: находит
форму входа по полю пароля, кнопки записи — по тексту «запис…», вид донации —
по слову «тромбоцит», даты и время — по формату текста, подтверждение — по
тексту кнопки. Любой шаг можно зафиксировать CSS-селектором в `config.yaml`.
Есть режим разведки (`recon`), который сохраняет скриншоты и HTML каждого шага
без подтверждения записи — по ним селекторы быстро уточняются.

## Капча (Яндекс SmartCaptcha)

Бот проходит капчу без участия человека, ручного режима нет:

1. **Чекбокс «Я не робот»** бот кликает сам внутри iframe капчи и ждёт токен.
   Чтобы Яндекс не показывал задание, бот работает в видимом браузере с
   постоянным профилем (`browser.profile_dir`): cookies и «репутация» браузера
   сохраняются между запусками, флаг автоматизации скрыт.
2. **Задание (картинки, слайдер)** решает сервис распознавания по API-ключу:
   rucaptcha.com или 2captcha.com (метод `yandex`, цена около 1 ₽ за решение).
   Ключ кладётся в `.env` как `CAPTCHA_API_KEY`, сервис выбирается в
   `config.yaml` → `captcha.solver`. Полученный токен бот подставляет в поле
   `smart-token` формы и отправляет её.

Без ключа бот пройдёт только чекбокс-вариант. Если Яндекс показал задание, а
ключа нет, сайт пропускается на этом круге с результатом `captcha_failed`,
и бот идёт к следующему сайту.

Капча проверяется перед отправкой формы входа, после неё (если появилась
только при отправке) и на каждом шаге формы записи.

## Установка

Нужен Python 3.11+.

```bash
git clone https://github.com/anoldyouth/blood-donor-bot.git
cd blood-donor-bot
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

Логин и пароль:

```bash
cp .env.example .env     # Windows: copy .env.example .env
```

и впишите в `.env` значения `DONOR_LOGIN`, `DONOR_PASSWORD` и, для капчи с
заданием, `CAPTCHA_API_KEY`. Файл `.env` в git не попадает.

## Первый запуск: проверить, что бот понимает сайт

1. Проверка входа на все три сайта:

   ```bash
   python -m donor_bot login-test
   ```

2. Разведка. Бот входит, открывает кабинет, нажимает кнопку записи, проходит
   форму и **останавливается перед кнопкой подтверждения**. Каждый шаг
   сохраняется в `runs/<дата>_recon/<сайт>/NN_<шаг>.png|html|json`, действия —
   в `trace_NN.json`, а найденный маршрут — в `learned/<сайт>.json`:

   ```bash
   python -m donor_bot recon
   python -m donor_bot recon --headful     # с видимым окном браузера
   ```

   Если кнопки записи сейчас нет (слоты закрыты), разведка покажет только
   кабинет — это тоже полезно. Лучше всего запускать её сразу после 12:00.

3. Пробный прогон без подтверждения:

   ```bash
   python -m donor_bot once --dry-run
   ```

   Результат `dry_run` означает, что бот дошёл до кнопки подтверждения.
   Результат `stuck` — бот не понял, что нажимать: смотрите дампы в
   `runs/` и задайте селекторы в `config.yaml` (`selectors:`).

4. Боевая попытка прямо сейчас (создаст реальную запись, если есть слот):

   ```bash
   python -m donor_bot once
   ```

## Постоянная работа

```bash
python -m donor_bot run
```

Бот ждёт 12:00 по Москве (за `start_before_sec` секунд заранее логинится на
всех сайтах), затем `window_min` минут по кругу проверяет сайты в порядке
приоритета каждые `retry_interval_sec` секунд. Так покрывается «плавающее»
время открытия слотов. После успеха записывает результат в `state.json`,
шлёт уведомление (в лог и, если настроено, в Telegram) и не пытается
записаться следующие `pause_days_after_success` дней. Снять паузу вручную:

```bash
python -m donor_bot clear-pause
```

Окно терминала должно оставаться открытым, а компьютер не должен спать в
12:00. Альтернатива — запускать `python -m donor_bot once --window 20` по
расписанию ОС в 11:59 (Планировщик заданий Windows, cron, launchd).

Другие команды: `next` — время следующего запуска, `-v` — подробный лог,
`--headful` — показать браузер. Лог пишется в `bot.log`.

## Что сохраняется после каждого прогона

Бот в любом режиме (`run`, `once`, `recon`) ведёт архив, чтобы ничего не
приходилось изучать заново:

| Где | Что |
|-----|-----|
| `runs/<дата_время>_<режим>/<сайт>/NN_<шаг>.png` | скриншот каждого шага: кабинет, форма, подтверждение |
| `runs/.../NN_<шаг>.html` | полный HTML страницы на этом шаге |
| `runs/.../NN_<шаг>.json` | все видимые кликабельные элементы: текст, классы, селектор, выключен ли, выбран ли; плюс все `<select>` с вариантами |
| `runs/.../trace_NN.json` | журнал действий попытки: роль шага (кнопка записи, вид донации, дата, время, согласие, подтверждение), что нажато, его CSS-селектор, адрес страницы, источник решения (эвристика / config / рецепт) |
| `runs/history.jsonl` | одна строка на каждое изменение результата: время, сайт, результат, сообщение сайта |
| `learned/<сайт>.json` | **рецепт записи** — селекторы всех шагов успешного (или dry-run) прохождения формы |

Повторяющиеся одинаковые страницы (кабинет без изменений каждые 4 секунды) в
архив не пишутся. Папки старше `archive.keep_days` дней удаляются.

**Рецепт применяется автоматически.** В следующем запуске бот сначала пробует
селекторы из `learned/<сайт>.json` (а для кнопок ещё и поиск по их тексту) и
только если элемент не найден или его текст не подходит роли, включает
эвристический поиск. Так после первого удачного прохождения запись идёт по
известному маршруту, быстрее и без угадывания. Удалите файл рецепта, если
сайт изменился и рецепт мешает.

Для доработки бота достаточно прислать папку последнего прогона из `runs/`
и `learned/`: там видно, как выглядела страница, что бот нажал и где
остановился. В HTML попадают данные кабинета (номер донора, группа крови),
учитывайте это при пересылке.

## Настройка (`config.yaml`)

* `sites` — порядок = приоритет.
* `schedule.time`, `start_before_sec`, `window_min`, `retry_interval_sec`.
* `booking.date_preference` — `earliest` (ближайшая дата) или `latest`.
* `booking.preferred_times` — список желаемых времён, например `["09:00", "09:30"]`;
  если пусто, берётся самое раннее свободное.
* `booking.dry_run: true` — никогда не нажимать подтверждение.
* `browser.headless: false` — видимый браузер (по умолчанию; так капча реже
  показывает задание). `true` — без окна.
* `browser.profile_dir` — папка постоянного профиля браузера; удалите её,
  чтобы начать «с чистого листа».
* `browser.channel: chrome` — использовать установленный Google Chrome вместо
  Chromium от Playwright.
* `captcha.solver` — `rucaptcha` или `2captcha`; `captcha.solve_timeout_sec` —
  сколько ждать ответа сервиса.
* `selectors` — переопределение любого шага CSS-селекторами (примеры в файле);
  имеют приоритет над рецептом из `learned/`.
* `archive.dir`, `archive.keep_days` — где и сколько хранить архив прогонов.
* `learning.enabled`, `learning.dir` — использовать и куда писать рецепты.

Уведомления в Telegram: заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в
`.env`.

## Тесты

`tests/fake_site.py` — имитация сайта с формой входа, кабинетом,
многошаговой формой записи, имитацией SmartCaptcha (чекбокс и задание) и
API сервиса распознавания. Тесты прогоняют эвристики бота через неё в
настоящем Chromium:

```bash
pip install pytest
python -m pytest tests -q
```

Имитацию можно поднять и вручную (`python tests/fake_site.py`), чтобы
посмотреть, как бот ведёт себя в `--headful` режиме, указав в `config.yaml`
сайт `http://127.0.0.1:8765`.
